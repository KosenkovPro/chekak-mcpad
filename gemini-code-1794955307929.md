## 1. Концепция и позиционирование

**MCPad** — это сверхбыстрый кроссплатформенный текстовый редактор и локально-облачная база знаний нового поколения на языке **Rust**. Продукт задуман как современная эволюция **Notepad++** и открытая, лёгкая альтернатива **Obsidian**, объединяющая:
1. Нативную производительность Rust при работе с большими файлами и логами;
2. Открытые стандарты хранения данных (`.md` и `.canvas`) без привязки к проприетарным форматам (нулевой vendor lock-in);
3. Бесконечный визуальный холст (уровня Draft.io / Obsidian Canvas);
4. Нативный офлайн/облачный голосовой ввод (Whisper);
5. Встроенный двусторонний **MCP-сервер (Model Context Protocol)**, превращающий локальное хранилище заметок и схем в живой контекст для AI-агентов (Claude Code, локальные LLM);
6. Гибридную фоновую синхронизацию (собственное хранилище пользователя бесплатно или облако `mcpad.chekak.store` по модели Open Core).

## 2. Технологический стек

### 2.1. Ядро (Rust Backend)
- **Текстовый буфер:** `ropey` — структура данных Rope для вставки, удаления и навигации по многомегабайтным файлам за $O(\log N)$ без фризов.
- **Полнотекстовый поиск и индексация:** `tantivy` (инвертированный индекс в стиле Lucene для мгновенного поиска по всему Vault) + `grep-searcher` / `ignore` (потоковый поиск без предварительной индексации по произвольным директориям).
- **Отслеживание файловой системы:** `notify` (кроссплатформенный file watcher с debounce-фильтрацией).
- **Парсинг и сериализация:** `serde`, `serde_json` (JSON Canvas 1.0), `pulldown-cmark` (AST-разбор Markdown, извлечение `[[wikilinks]]`, тегов `#tag` и frontmatter YAML/TOML).
- **Голосовой ввод (Speech-to-Text):** `whisper-rs` (биндинги к `whisper.cpp`) или `ort` (ONNX Runtime с аппаратным ускорением CPU/GPU) для локальной офлайн-транскрибации речи.
- **MCP-сервер:** `rmcp` / кастомная реализация JSON-RPC 2.0 поверх `stdio` и локального HTTP/SSE (`axum` + `tokio`).
- **Криптография и синхронизация:** `sha2` (SHA-256 хэширование файлов и чанков), `reqwest` (HTTP/3 и REST), `rust-s3` / `aws-sdk-s3` (S3-совместимые хранилища), `git2` (опциональный Git-синк).

### 2.2. Слой пользовательского интерфейса (UI)
- **Основной рекомендуемый вариант:** **Tauri v2** (лёгкий Rust-хост + системный WebView2/WebKitGTK без тяжелого Chromium/Electron, размер бинарника ~10–15 МБ) + **CodeMirror 6** (текстовый редактор под MIT) + **React Flow (`@xyflow/react`)** (бесконечный 2D-холст под MIT).
- **Альтернативный нативный вариант (без WebView):** чистый GPU-рендер на `egui` + `cosmic-text` (верстка шрифтов и многострочный ввод) + `egui-snarl` (нодовый граф для холста).

## 3. Подробное описание функциональных модулей

### 3.1. Быстрый текстовый редактор (Эволюция Notepad++)
- **Мгновенный старт и работа с тяжёлыми файлами:** открытие логов и дампов размером сотни мегабайт без загрузки всего файла в единый `String`.
- **Мультитаб и сплит-панели:** вкладки, разделение окна по вертикали и горизонтали, закрепление вкладок, восстановление несохранённых черновиков при перезапуске (hot exit).
- **Работа с кодировками и окончаниями строк:** автоопределение и конвертация на лету (`UTF-8`, `UTF-8 with BOM`, `UTF-16 LE/BE`, `Windows-1251`, `KOI8-R`), переключение `LF` / `CRLF`.
- **Подсветка синтаксиса и режимы просмотра:** поддержка всех основных языков программирования, JSON/YAML/TOML/SQL/Markdown, сворачивание блоков (code folding), мультикурсоры, поиск и замена по регулярным выражениям (PCRE/Rust regex) с предпросмотром.
- **CLI-интеграция:** запуск из терминала командой `mcpad` или `ckm`:
  - `ckm file.log` — открыть конкретный файл;
  - `ckm .` — открыть текущую директорию как рабочее пространство (Vault);
  - `ckm board.canvas` — открыть бесконечный холст;
  - `echo "text" | ckm` — принять вывод из `stdin` в новую вкладку.

### 3.2. База знаний и открытые форматы (Совместимость с Obsidian)
- **Local-First Vault:** хранилище представляет собой обычную папку на диске пользователя. Никаких закрытых баз данных: пользователь может открыть ту же папку параллельно в Obsidian, VS Code или любом другом редакторе.
- **Поддержка Markdown (`.md`):**
  - Двусторонние вики-ссылки `[[Название заметки]]` и `[[Название заметки#Заголовок|Алиас]]` с автодополнением при вводе `[[`.
  - Автоматическое обновление ссылок во всех файлах при переименовании или перемещении заметки.
  - Панель обратных ссылок (Backlinks) и несвязанных упоминаний.
  - Поддержка YAML Frontmatter (метаданные заметки: теги, статусы, даты, алиасы).
- **Интерактивный граф связей:** визуализация связей между заметками и `.canvas`-досками в реальном времени с фильтрацией по тегам и директориям.

### 3.3. Бесконечный холст (Аналог Draft.io / Obsidian Canvas)
- **Формат хранения:** строгое соответствие открытой спецификации **JSON Canvas 1.0** (расширение `.canvas`, лицензия MIT). Файлы `.canvas` полностью совместимы с Obsidian в обе стороны.
- **Поддерживаемые типы узлов (`nodes`):**
  1. `text` — карточка с полноценным Markdown-редактированием внутри ноды;
  2. `file` — встроенная карточка-ссылка на любой `.md`, `.png/.jpg/.svg`, `.pdf` или код из Vault (изменения в файле мгновенно отражаются на доске и наоборот);
  3. `link` — карточка веб-ссылки с предпросмотром;
  4. `group` — визуальный контейнер-рамка для логической группировки карточек (аналог фреймов в Draft.io) с возможностью перемещать всю группу целиком.
- **Связи (`edges`):** направленные и двунаправленные стрелки между любыми сторонами узлов (`top`, `right`, `bottom`, `left`), текстовые подписи на линиях (`label`), цветовая кодировка.
- **Управление холстом:** плавный зум и панорамирование, привязка к сетке (snap-to-grid), выравнивание карточек, экспорт доски в PNG/SVG/Markdown-конспект.

### 3.4. Встроенный MCP-сервер (Model Context Protocol)
MCPad выступает как нативный сервер контекста для любых MCP-совместимых AI-клиентов (**Claude Code**, **Cursor**, **Cline**, локальные агенты через Ollama / llama.cpp).
- **Транспорты:**
  - `stdio` — для прямого запуска агентом в качестве дочернего процесса (`ckm mcp-serve --vault /path/to/vault`);
  - `HTTP / SSE` — локальный защищённый сокет (`127.0.0.1:<port>`) для подключения к уже запущенному GUI-окну редактора в реальном времени.
- **Предоставляемые MCP Resources:**
  - `mcpad://vault/tree` — актуальное дерево файлов и директорий;
  - `mcpad://editor/active` — содержимое текущей открытой вкладки, позиция курсора и выделенный пользователем фрагмент текста;
  - `mcpad://note/{path}` — содержимое конкретной `.md`-заметки с её метаданными и обратными ссылками;
  - `mcpad://canvas/{path}` — структурированный JSON-граф указанной `.canvas`-доски.
- **Предоставляемые MCP Tools:**
  - `search_vault(query, limit, tags)` — полнотекстовый и семантический поиск по базе знаний;
  - `read_note(path)` / `write_note(path, content, mode)` — чтение, создание или точечное редактирование секций заметки;
  - `append_to_active_buffer(text)` — вставка сгенерированного агентом текста/кода прямо в активное окно редактора;
  - `canvas_create_node(canvas_path, node_data)` / `canvas_connect_nodes(...)` — программное создание карточек, групп и стрелок на бесконечном холсте (например, построение архитектурной схемы по кодовой базе);
  - `get_backlinks(path)` — получение графа зависимостей заметки.

### 3.5. Нативный голосовой ввод (Speech-to-Text + AI)
- **Активация:** глобальный или оконный хоткей (Push-to-Talk или Toggle-режим) с визуальным индикатором уровня звука.
- **Движок распознавания:**
  - **Локальный режим (бесплатно, офлайн):** встроенный движок Whisper (`whisper-rs` / ONNX Runtime) с выбором модели (`tiny`, `base`, `small`, `medium`, `large-v3-turbo`) и автоматическим определением языка (русский / английский / смешанный IT-сленг).
  - **Облачный режим (через `mcpad.chekak.store`):** отправка сжатого аудио (Opus) на GPU-кластер ЧёКак для сверхбыстрой транскрибации на слабых ноутбуках без видеокарты.
- **Сценарии использования:**
  1. **Прямая диктовка в текст:** мгновенная вставка распознанного текста в позицию курсора в `.md` или любом открытом файле с базовой расстановкой пунктуации.
  2. **Голосовой брейншторм на `.canvas`:** пользователь наговаривает поток мыслей на открытой доске $\rightarrow$ локальная или облачная LLM через MCP автоматически разбивает монолог на тезисы, создаёт отдельные карточки `text`, объединяет их в тематические рамки `group` и расставляет логические стрелки `edges`.

## 4. Архитектура гибридной синхронизации и модель монетизации (Open Core)

Модуль синхронизации строится по принципу **Local-First**: все операции чтения и записи в интерфейсе происходят исключительно с локальным диском за микросекунды. Синхронизация работает в фоновом асинхронном пуле потоков (`tokio`) и не блокирует UI.

### 4.1. Модель распространения (Open Core / Freemium)

| Уровень тарифа | Где хранятся данные | Стоимость | Возможности и лимиты |
| :--- | :--- | :--- | :--- |
| **1. Local Only** | Только локальный диск ПК | **Бесплатно (Apache-2.0)** | Полный функционал редактора, `.canvas`, локальный Whisper, встроенный MCP-сервер. Без регистрации. |
| **2. BYO Storage (Своё хранилище)** | S3 (MinIO, Cloudflare R2, AWS), WebDAV (Nextcloud), Git | **Бесплатно (Apache-2.0)** | Неограниченная синхронизация между любым числом устройств пользователя через его собственную инфраструктуру. |
| **3. ЧёКак Cloud — Free Tier** | Облако `mcpad.chekak.store` | **Бесплатно** (по аккаунту Keycloak SSO `chekak.store`) | Синхронизация «из коробки» без настройки серверов: **1 Vault, лимит объёма до 150 МБ** (достаточно для тысяч текстовых `.md` и `.canvas` файлов). |
| **4. ЧёКак Cloud — Pro** | Облако `mcpad.chekak.store` | **Платно** (подписка или оплата внутренней валютой **Чики**) | Неограниченное количество Vault-проектов, увеличенное хранилище (от 10 ГБ под медиа, PDF и аудио), история версий файлов (snapshots за 30–90 дней), совместный доступ к `.canvas`-доскам по ссылке, облачный Whisper и облачные LLM-модели. |

### 4.2. Внутреннее устройство движка синхронизации (`SyncEngine`)

Чтобы клиент одинаково работал и с облаком `mcpad.chekak.store`, и с пользовательским S3/WebDAV, в Rust-ядре вводится единая абстракция — трейт **`SyncProvider`**:

```rust
#[async_trait]
pub trait SyncProvider: Send + Sync {
    /// Получить удалённый манифест состояния всех файлов в Vault
    async fn fetch_remote_manifest(&self, vault_id: &str) -> Result<RemoteManifest, SyncError>;

    /// Загрузить изменённый файл в удалённое хранилище
    async fn upload_blob(&self, vault_id: &str, rel_path: &str, data: Bytes, meta: FileMeta) -> Result<RemoteVersion, SyncError>;

    /// Скачать файл из удалённого хранилища
    async fn download_blob(&self, vault_id: &str, rel_path: &str) -> Result<(Bytes, FileMeta), SyncError>;

    /// Удалить файл (перемещение в удалённую корзину / soft-delete)
    async fn delete_blob(&self, vault_id: &str, rel_path: &str, expected_rev: u64) -> Result<(), SyncError>;
}
